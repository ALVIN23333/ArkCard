# 项目运行配置清单（克隆后必读）

本文说明从 Git 仓库克隆本项目后，**需要配置哪些内容才能正常运行**。

按需求层次分为三档：

| 档位 | 目标 | 是否需要额外配置 |
| --- | --- | --- |
| **第 1 档：跑起游戏** | 打开项目、进 Play Mode、与 AI 对战 | 只需安装 Unity，无需任何密钥 |
| **第 2 档：启用 LLM 战术建议** | AI 调用大模型辅助决策 | 需要一个 API Key（环境变量） |
| **第 3 档：重训 AI 模型** | 重跑自研训练链路、产出 ONNX | 需要配置 Python 环境与训练构建 |

---

## 1. 第 1 档：跑起游戏（必需）

### 1.1 安装 Unity

| 项目 | 要求 |
| --- | --- |
| Unity 版本 | **2022.3.62f3c1**（见 `ProjectSettings/ProjectVersion.txt`） |
| 安装方式 | Unity Hub → 安装 → 选择 `2022.3.62f3c1` |
| 必需模块 | Windows Build Support（如需构建）；其余按需 |

> **版本必须一致。** 用 2022.3 系列的其他补丁版本打开通常可以，但低于 2022.3 会因
> 序列化格式与包依赖不匹配而报错。如果 Hub 里没有 `62f3c1`，可以在
> Unity 下载归档页找到该版本，或用同系列相邻版本并在打开时接受升级提示。

### 1.2 打开项目并等待包解析

用 Unity Hub 打开项目根目录。首次打开时 Unity 会自动：

1. 重新生成 `Library/`（该项目录已被 `.gitignore` 排除，必须重新生成）
2. 从网络下载 `Packages/manifest.json` 中声明的依赖

**依赖中有 4 个来自 Git 仓库，需要能访问外网：**

| 包 | 来源 |
| --- | --- |
| `cn.unity.uos.launcher` | `https://cnb.cool/unity/uos/UOSLauncher.git` |
| `com.gamebooom.unity.mcp` | `https://github.com/FunplayAI/funplay-unity-mcp.git#v0.6.2` |
| `com.mirror.steamworks.net` | `https://github.com/Chykary/FizzySteamworks.git?path=/com.mirror.steamworks.net` |
| `com.rlabrecque.steamworks.net` | `https://github.com/rlabrecque/Steamworks.NET.git?path=/com.rlabrecque.steamworks.net` |

其余包来自 Unity 官方注册表。`Packages/packages-lock.json` 已随仓库提交，
用于锁定各包的具体版本，保证不同机器上解析结果一致。

> 若单位网络无法访问 GitHub，会导致包解析失败、项目无法编译。
> 处理方式：换网络、配置代理，或临时把这些包从 `manifest.json` 中移除
> （注意：移除 Mirror / Steamworks 相关包会影响联网对战功能，单机对战不受影响）。

### 1.3 打开场景并运行

1. 打开 `Assets/Scenes/BattleScene.unity`
2. 点 Play
3. 应能与 AI 对战，Console 出现：

```
[AI ML] Falling back to legacy MCTS: AI model config is not assigned.
```

**这条是正常的**，原因见 1.4。此时 AI 使用旧启发式 MCTS，功能完整。

### 1.4 为什么不需要提供 AI 模型

模型权重受 `.gitignore` 约束（`/Assets/AI/Models/`），**不随仓库提交**：

```gitignore
/Assets/AI/Models/
/Tools/exports/
/Artifacts/AI/
```

因此克隆后 `Assets/AI/Configs/DefaultAIModelConfig.asset` 里引用的
`policyModel` / `valueModel` 两个 ONNX 资源**是缺失的**（GUID 无法解析）。

项目对此有完整降级设计，**不需要你做任何额外操作**：

```csharp
// Assets/Scripts/AI/ML/Planning/AIPlannerFactory.cs
public static IAIPlanner Create(AIModelConfig modelConfig, MCTSSettings legacySettings, int? seed = null)
{
    MCTSPlanner fallback = new(legacySettings, seed);
    if (modelConfig == null)
    {
        return new ResilientAIPlanner(null, fallback, "AI model config is not assigned.");
    }
    try
    {
        BarracudaPolicyValueProvider provider = new(modelConfig);
        NeuralMCTSPlanner primary = new(provider, modelConfig.CreateSearchSettings(), seed);
        return new ResilientAIPlanner(primary, fallback);
    }
    catch (Exception exception)
    {
        return new ResilientAIPlanner(null, fallback, exception.Message);
    }
}
```

模型缺失或校验失败 → 打印一条警告 → 回退规则 MCTS → **游戏照常进行，不会崩溃**。

另外，仓库内 `DefaultAIModelConfig.asset` 记录的 `featureSchemaVersion: 1` 与运行时
schema v2 并不匹配，即便把旧模型放回去也会被 `AIModelConfig.Validate()` 拒绝。
**所以第 1 档无需任何模型文件。**

### 1.5 第 1 档验收清单

- [ ] Unity 能用 **2022.3.62f3c1** 打开项目，无编译错误（Console 无 `error CS`）
- [ ] 所有包解析完成（`Packages` 下无报错、`Assets/Mirror` 等目录存在）
- [ ] `Assets/Scenes/BattleScene.unity` 能打开
- [ ] Play Mode 下能与 AI 打完整一局
- [ ] Console 中的 ML-Agents 警告属于预期降级，不是故障

## 2. 第 2 档：启用 LLM 战术建议（可选）

未配置时 AI 仍然可用，只是不调用大模型。要启用需要提供 **API Key**。

### 2.1 需要配置的内容

| 项目 | 说明 |
| --- | --- |
| 环境变量名 | `ARKCARD_LLM_API_KEY` |
| 取值 | 智谱开放平台 API Key，从 <https://open.bigmodel.cn> → API Keys 创建 |
| 接口地址 | `https://open.bigmodel.cn/api/paas/v4/chat/completions`（代码内默认值，无需配置） |
| 默认模型 | `glm-4-plus`（代码内默认值，可在 Inspector 改） |

### 2.2 配置步骤

```powershell
# 1) 复制示例文件（可选，仅作为填写参考）
Copy-Item .env.example .env
# 编辑 .env 填入 Key；.env 已被 .gitignore 排除，不会提交

# 2) 彻底退出 Unity 与 Unity Hub —— 环境变量是进程启动时读取的
Get-Process Unity -ErrorAction SilentlyContinue | Stop-Process -Force
Get-Process 'Unity Hub' -ErrorAction SilentlyContinue | Stop-Process -Force

# 3) 设置环境变量
$env:ARKCARD_LLM_API_KEY = '你的Key'

# 4) 从【同一个窗口】启动 Unity（不要用 Hub 点，Hub 继承不到该变量）
& "C:\Program Files\Unity\Hub\Editor\2022.3.62f3c1\Editor\Unity.exe" -projectPath "D:\UnityProjects\ArkCard\ArkCard-main"
```

**为什么必须从同一终端启动**：Unity 在启动时读取环境变量。先开 Unity 再设变量、
或让 Unity Hub 代为拉起，都读不到。详细说明见 `环境变量与密钥管理.md`。

### 2.3 场景侧开关

打开 `BattleScene.unity`，选中 Hierarchy 的 `player2`，在 `AIController` 组件上确认
（仓库中这两个开关已保存为开启状态，通常无需改动）：

- `Enable LLM Strategy` ✅
- `Enable Ai Debug Log` ✅（打开后才能在 Console 看到 LLM 采纳日志）

### 2.4 验证

进 Play Mode，先结束自己的回合让 AI 决策，Console 应出现：

```
[AI Hybrid] LLM=<策略文本>, confidence=0.90, action=EndTurn
```

若需要单独测试 API 通道（不必打完整局），可用组件右键菜单：
选中 `player2` → `LLM Strategy Client` 组件标题右侧 `⋮` →
`ArkCard/测试 LLM 调用（仅编辑器）`。

### 2.5 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| Console 完全没有 LLM 日志，AI 照常出牌 | 未设置环境变量，或 Unity 启动时未继承 | 按 2.2 重做，确认"先设变量再从同一终端启动" |
| 出现 `环境变量 ARKCARD_LLM_API_KEY 未设置，测试取消` | 同上 | 同上 |
| `Request failed: HTTP/1.1 401` | Key 错误 / 过期 | 到控制台确认 Key，或用 `提交材料/llm_test.py` 单独验证 |
| `code 1210 temperature参数非法` | 旧版代码未做 2 位小数格式化 | 拉取最新代码（本项目已修复） |
| `Cannot deserialize ArrayList<ChatMessage> from Object value` | 旧版代码用 `JsonUtility` 序列化了顶层数组 | 同上，已修复 |
| `Invalid JSON response` | 模型返回被 Markdown 代码块包裹 | 已用 `StripCodeFence()` 兼容；仍失败可换 `glm-4-plus` |

## 3. 第 3 档：重训 AI 模型（可选，仅在需要重新训练时）

日常运行与演示**不需要**这一档。以下内容仅在需要重跑训练链路时使用。

### 3.1 被忽略的训练相关文件

| 路径 | 是否随仓库提交 | 缺失后果 |
| --- | --- | --- |
| `Tools/AITraining/`（训练源码） | ✅ 提交 | — |
| `Tools/AITraining/configs/*.toml` | ✅ 提交 | — |
| `Tools/AITraining/.venv/` | ❌ 忽略 | 需自行创建虚拟环境 |
| `Artifacts/AI/Datasets/`（教师数据） | ❌ 忽略 | 需重新生成（实测约 42.6 MB） |
| `Tools/runs/`（训练运行记录） | ❌ 忽略 | 仅用于续训，可按需重建 |
| `Assets/AI/Models/`（ONNX 权重） | ❌ 忽略 | 需重新训练导出 |
| `Builds/MLAgentsTraining/`（训练构建） | ❌ 忽略 | 需在 Unity 内重新构建（实测约 185 MB） |

### 3.2 配置 Python 环境

要求 Python **>= 3.10**（见 `Tools/AITraining/pyproject.toml`）。

```powershell
cd Tools/AITraining

# 创建虚拟环境
python -m venv .venv
.\.venv\Scripts\Activate.ps1

# 可编辑安装（含导出与测试的额外依赖）
pip install -e ".[export,dev]"
```

主要依赖：`numpy`、`torch>=2.2`、`onnx`、`onnxruntime`、`pytest`、`tomli`（Python < 3.11）。

### 3.3 构建 ML-Agents 训练环境

ML-Agents 训练需要一个可被 `mlagents-learn` 拉起的玩家构建。该项目未随仓库提交，
需自行生成：

1. 在 Unity 中打开项目
2. 菜单 `File > Build Settings`，切换到目标平台（Windows x86_64）
3. 把场景加入构建列表（`Assets/Scenes/BattleScene.unity`）
4. 输出到 `Builds/MLAgentsTraining/ArkCardTraining.exe`
5. 点 Build

> 该路径与 `Artifacts/MLAgents/*/configuration.yaml` 里的 `env_path` 一致。
> 项目 `Logs/BuildMLAgents.log` 中记录了历史上一次成功构建（`Build Finished, Result: Success`）。

### 3.4 安装 ML-Agents Python 包

```powershell
pip install mlagents==0.30.0
mlagents-learn --version
```

### 3.5 执行训练

```powershell
cd Tools/AITraining

# 复制一份配置（每轮一份，不要覆盖历史轮次）
Copy-Item configs\round.toml configs\round3.toml

# 生成教师数据
arkcard-pipeline generate-teacher --config configs/round3.toml

# 训练
arkcard-pipeline train --config configs/round3.toml

# 导出 ONNX 并暂存为候选模型
arkcard-pipeline candidate --config configs/round3.toml

# 竞技场评测（达到门槛才允许替换冠军模型）
arkcard-pipeline arena --config configs/round3.toml
```

ML-Agents 侧的 PPO 训练（独立于上面的自研链路）：

```powershell
mlagents-learn ../../Assets/AI/Configs/mlagents_card_battle.yaml --run-id=ArkCardPPOProbe
```

### 3.6 重训前的维度核对（当前是一致对齐的）

**C# 与 Python 的编码维度已经对齐，可以直接重训，无需先改维度。**

| 来源 | 状态维度 | 策略输入维度 |
| --- | --- | --- |
| C# 编码器（`AIEncodingSchema`，schema v2） | 2180 | 2919 |
| Python 常量（`Tools/AITraining/arkcard_ai/dataset.py`） | 2180 | — |
| 导出器契约（`pipeline.py`） | 2180 | 2919 |
| 磁盘数据集（`Artifacts/AI/Datasets/teacher-v2`） | 2180 | — |

数值推导（与 `AIEncodingSchema.cs` 完全一致）：

```
MaxHandCards = 10,  MaxFieldCards = 5
VisibleCardSlotCount    = 10 + 5 + 5 = 20          # 手牌 + 己方场面 + 敌方场面
CardSummarySlotCount    = 4
CardFeatureCount        = 90                       # EffectType 扩至 34 后每张卡的语义特征数

StateFeatureCount  = 20 + (20 + 4) * 90 = 2180
ActionFeatureCount = 5 + 6 + 1 + 90 + 1 + 6 * 106 = 739
PolicyInputFeatureCount = 2180 + 739 = 2919
```

**校验方法**：直接用项目自带工具验证数据集头部与解析是否正确：

```powershell
cd Tools/AITraining
python -m arkcard_ai.inspect_dataset ..\..\Artifacts\AI\Datasets\teacher-v2
```

若头部维度不匹配，`dataset._read_header()` 会抛出
`incompatible dataset header: expected (...), got (...)`；能正常输出统计即说明一致。
（实测该命令读取 49 个分片、100002 条样本，无报错。）

> 修改 `CardFeatureCount`（例如再新增效果枚举）时，必须同时更新：
> `AIEncodingSchema.cs` 的 `CardFeatureCount` 与 `Version`、
> `arkcard_ai/dataset.py` 的 `STATE_FEATURE_COUNT` / `ACTION_FEATURE_COUNT` / `SCHEMA_VERSION`、
> `pipeline.py` 的导出契约数值，并重新生成训练数据。任一处漏改都会在读取分片时报头部不兼容。

详见 `AI集成方案设计文档_V2.md` 第 2.4 节。
