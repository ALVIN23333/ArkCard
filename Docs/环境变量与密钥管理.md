# 环境变量与密钥管理

本文说明 ArkCard 项目中大语言模型 API 密钥的存放方式，以及在多人协作 / 上传 Git 仓库时
如何安全处理。

---

## 1. 设计原则：密钥不进仓库

项目对 LLM API 密钥的处理遵循三条规则：

1. **代码里不硬编码。** `LLMStrategyClient` 只从**环境变量**读取密钥：

   ```csharp
   [SerializeField] private string apiKeyEnvironmentVariable = "ARKCARD_LLM_API_KEY";
   ...
   string apiKey = Environment.GetEnvironmentVariable(apiKeyEnvironmentVariable);
   if (string.IsNullOrWhiteSpace(apiKey) || state == null || legalActions == null || legalActions.Count == 0)
   {
       onComplete?.Invoke(null);   // 没有 Key 就不发请求，AI 继续用本地规划器
       yield break;
   }
   ```

2. **场景与资源里不保存。** 该组件在场景中**没有序列化实例**——它由
   `AIController.ResolveLLMClient()` 在运行时自动 `AddComponent` 挂载，
   所以 Inspector 上不会残留密钥，`BattleScene.unity` 里只有开关布尔值。

3. **仓库里不放真实值。** 只提交 `.env.example`（仅含变量名），
   `.env` 与各文件均由 `.gitignore` 排除。

因此，**克隆仓库的人拿到的是一个"需要自己提供密钥"的项目**，而不是一个自带密钥的项目。
这是正确且安全的做法。

---

## 2. 涉及的环境变量

| 变量名 | 必需 | 说明 |
| --- | --- | --- |
| `ARKCARD_LLM_API_KEY` | 使用 LLM 功能时必需 | 智谱开放平台 API Key。未设置时 LLM 通道直接跳过，不影响对局 |
| `ARKCARD_LLM_MODEL` | 可选 | 默认模型名，代码内已有默认值 `glm-4-plus`，一般无需设置 |

## 3. 本地设置方法（三种，按场景选）

### 方式 A：命令行临时设置（推荐，最安全）

密钥只存在于当前终端会话，关掉窗口即失效，不落盘。

```powershell
# 1) 彻底退出 Unity 与 Unity Hub
Get-Process Unity -ErrorAction SilentlyContinue | Stop-Process -Force
Get-Process 'Unity Hub' -ErrorAction SilentlyContinue | Stop-Process -Force

# 2) 在 PowerShell 里设置（注意：只对当前窗口及其子进程有效）
$env:ARKCARD_LLM_API_KEY = '你的Key'

# 3) 从【同一个窗口】启动 Unity —— 不要用 Unity Hub 点，
#    因为 Hub 会把它自己的环境传给子进程，而 Hub 并没有这个变量
& "C:\Program Files\Unity\Hub\Editor\2022.3.62f3c1\Editor\Unity.exe" -projectPath "D:\UnityProjects\ArkCard\ArkCard-main"
```

> **为什么必须从同一窗口启动**：Unity 在**启动时**读取环境变量。
> 先开 Unity 再设变量，或者让 Hub 去拉 Unity，都读不到。

### 方式 B：用户级环境变量（一次设置，长期有效）

```powershell
setx ARKCARD_LLM_API_KEY "你的Key"
# 之后需要重启 Unity Hub 与 Unity（已运行的进程不会自动获得新变量）
```

- 优点：之后随便怎么启动都行。
- 缺点：密钥**明文写入注册表** `HKCU\Environment` 并长期存在，共用电脑上不推荐。
- 清理：

  ```powershell
  reg delete HKCU\Environment /F /V ARKCARD_LLM_API_KEY
  ```

### 方式 C：`.env` 文件（便于团队共享配置流程）

```powershell
Copy-Item .env.example .env
# 然后编辑 .env，填入 ARKCARD_LLM_API_KEY=你的Key
```

`.env` 已在 `.gitignore` 中排除。注意 Unity 本身**不会自动加载** `.env`，
需要由启动脚本注入，例如：

```powershell
# 在启动 Unity 前读取 .env 并注入当前进程环境
Get-Content .env | Where-Object { $_ -match '^([A-Z_]+)=(.*)$' } | ForEach-Object {
    $name, $value = $_ -split '=', 2
    Set-Item -Path "Env:$name" -Value $value.Trim()
}
& "C:\Program Files\Unity\Hub\Editor\2022.3.62f3c1\Editor\Unity.exe" -projectPath $PWD
```

## 4. 克隆本仓库后如何跑起来

仓库里**没有**密钥。新环境按以下顺序操作：

1. 用 Unity Hub 打开项目（首次会重新导入 `Library/`，耗时较长）。
2. 确认 `Assets/Scripts/AI/LLM/LLMStrategyClient.cs` 存在（LLM 客户端代码随仓库提供）。
3. 按第 3 节任一方式提供 `ARKCARD_LLM_API_KEY`，并从该终端启动 Unity。
4. 打开 `Assets/Scenes/BattleScene.unity`。
5. 选中 `player2`，在 `AIController` 上确认：
   - `Enable LLM Strategy` 已勾选（默认在场景中已保存为 `1`）
   - `Enable Ai Debug Log` 已勾选，便于在 Console 看到采纳日志
6. 进入 Play Mode，先结束自己的回合，让 AI 决策一次。
   控制台出现下面这行即表示 LLM 通道正常：

   ```
   [AI Hybrid] LLM=<策略文本>, confidence=0.90, action=EndTurn
   ```

**不需要密钥也能跑。** 未配置 `ARKCARD_LLM_API_KEY` 时，`RequestHint` 在入口直接返回，
AI 继续使用本地规划器（旧启发式 MCTS），对局功能完整、不会崩溃。
这一点是刻意设计的降级行为。

## 5. 上传 Git 仓库前的自检

### 5.1 已配置的忽略规则

`.gitignore` 已包含以下安全规则：

```gitignore
# 本密钥与本地私有配置
.env
.env.*
!.env.example
*.env
secrets.json
secrets/
UserSecrets/
*.local.json

# 根目录的临时截图/录屏（可能含明文 Key、账号、本机路径）
/*.png
/*.jpg
/*.jpeg
/*.mp4
/*.mov
/*.webp
```

### 5.2 上传前必查的三件事

**① 确认 `.env` 没有被跟踪**

```powershell
git status --short | Select-String '\.env'
# 期望：只出现 .env.example（若出现 .env，说明没被忽略，需检查 .gitignore）
git check-ignore -v .env
# 期望：输出 .gitignore 中匹配的那一行
```

**② 确认代码与资源里没有明文密钥**

```powershell
# 扫描全部文本文件是否有 sk- 开头的密钥串
Get-ChildItem -Recurse -File |
  Where-Object { $_.Extension -notin '.png','.jpg','.dll','.pdb','.onnx','.pt','.gz','.zip','.exe' } |
  Select-String -Pattern 'sk-[0-9a-fA-F]{16,}' |
  Select-Object Path, LineNumber
# 期望：无输出
```

**③ 确认截图里没有明文 Key**

这是本项目**最容易出错的地方**。以下文件曾经包含明文 Key，请勿提交：

| 文件 | 情况 | 处理 |
| --- | --- | --- |
| `提交材料/LLM API调用测试/设置ARKCARD_LLM_API_KEY.png` | 原图第一行有完整 Key | 已在 `.gitignore` 排除；若必须提交，先删除该文件或用画图打码覆盖 |
| `提交材料/LLM API调用测试/19_调用确认_1.png`、`_2.png` | 由上一张**裁剪**而来，已不含 Key | 可安全提交 |
| 项目根目录的 `1.png` ~ `12.png` 等 | 逐条排查时的临时截图，部分含明文 Key | 已在 `.gitignore` 排除（`/*.png`） |

### 5.3 仓库内容建议

| 目录 | 建议 | 原因 |
| --- | --- | --- |
| `Assets/`、`Packages/`、`ProjectSettings/` | 提交 | 项目本体 |
| `Tools/AITraining/`（Python 训练代码） | 提交 | 训练链路源码 |
| `Docs/`、`new/`、`README` | 提交 | 文档与改动副本 |
| `Library/`、`Temp/`、`Logs/`、`obj/`、`Builds/` | 忽略 | Unity 生成物，体积大且可重建（`.gitignore` 已含） |
| `Artifacts/AI/`、`Assets/AI/Models/`、`Tools/exports/` | 忽略 | 数据集与模型权重，体积大（`.gitignore` 已含） |
| `提交材料/` | **斟酌** | 含实验报告与截图，适合随作业提交，但注意其中的 Key 截图 |
| 根目录 `*.png`（排查截图） | 忽略 | 可能含密钥与本机信息（`.gitignore` 已含） |

## 6. 如果密钥已经泄露了怎么办

**密钥一旦提交过，仅"删除文件"是不够的** —— Git 历史里仍然保留，必须视为已泄露。

处理步骤：

1. **立即吊销旧密钥**：登录 <https://open.bigmodel.cn> → API Keys →
   删除泄露的那个 Key。这一步最重要，做在其它所有事情之前。
2. **生成新密钥**，按第 3 节方式在本地配置。
3. 若仓库已经推送过，视情况清理历史（个人作业仓库通常直接删库重建更快）：
   - 简单做法：`git rm --cached <文件>` + 提交 + 强推，但历史仍在
   - 彻底做法：使用 `git filter-repo` 或 BFG 重写历史，然后强推
   - 最省事做法：删除远端仓库、重建、用当前（已清理的）工作区重新推送

> **本项目的情况**：上传前尚未初始化 Git 仓库，**没有任何历史提交**，
> 因此不存在"历史里残留密钥"的问题。只要按第 5 节自检后首次推送即可。

## 7. 常见问题

**Q：为什么不用 `ScriptableObject` 或配置文件存 Key？**
A：那会把密钥写进 `Assets/`，一旦提交就随仓库泄露，而且 Unity 会在 Inspector 里明文显示。
环境变量的好处是密钥与代码彻底分离，同一份代码可被不同的人用不同的密钥运行。

**Q：CI / 服务器上怎么提供 Key？**
A：用平台提供的 Secret 机制（GitHub Actions 的 `secrets`、GitLab CI 的 `CI/CD Variables`），
在流程里注入为环境变量，不要写进仓库里的任何文件。

**Q：能不能提交一个"演示用"的 Key？**
A：不能。任何提交进仓库的 Key 都应视为公开信息。演示时用第 3 节方式临时设置，
或者干脆不设——未配置时 AI 会回退到本地规划器，演示依然完整可跑。
