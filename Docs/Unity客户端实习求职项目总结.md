# Unity 客户端实习求职项目总结

> 用途：用于后续修改简历、准备面试项目讲解和梳理求职方向。本文只基于当前项目与已有简历材料整理，重点服务 Unity 游戏客户端实习投递。

## 一、专业技能精简版

- **Unity / C#**：熟悉 Unity 2022 LTS 开发流程，掌握 C# 面向对象、集合、泛型、委托、事件、协程、Task、反射等常用能力，能够独立完成玩法模块开发与调试。
- **玩法与战斗系统**：具备卡牌、回合制、数值结算、状态/被动、目标选择、动画流程等客户端玩法系统开发经验，关注规则一致性与可扩展性。
- **数据驱动与编辑器工具**：熟悉 ScriptableObject 数据配置，能够使用 EditorWindow、UI Toolkit、SerializedObject、Undo 和 AssetDatabase 构建可视化编辑器工具，降低配置和维护成本。
- **性能与调试**：有对象池、对象复用、低 GC 分配、异步场景加载、运行时 GM 调试面板、动画跳过与时间倍率等实践经验，能围绕性能瓶颈和验证效率优化开发流程。
- **工程协作与测试**：使用 Git 管理项目，了解 asmdef 程序集拆分，能够基于 Unity Test Framework 编写 EditMode / PlayMode 测试，覆盖核心规则和完整对局流程。

## 二、主项目：明日方舟卡牌

**明日方舟卡牌 | Unity 2D 策略卡牌对战 | 独立开发**

**技术栈**：Unity 2022 LTS / C# / UGUI / ScriptableObject / EditorWindow + UI Toolkit / Unity Test Framework / MCTS / PrimeTween

**项目概述**：独立开发的 2D 策略卡牌对战项目，包含卡牌数据配置、手牌与场地管理、回合流程、卡牌效果结算、目标选择、AI 托管、编辑器工具、自动化测试和调试面板等完整客户端链路。

### 可写入简历的项目要点

- **设计数据驱动卡牌系统**：使用 `CardData` 和 `CardListSO` 管理卡牌 ID、类型、费用、攻击、生命、图片、音效、被动、效果与 AI 参数，使新增卡牌主要通过配置完成，减少硬编码和重复逻辑。
- **重构统一效果系统**：设计 `EffectRegistry` 作为卡牌效果统一入口，通过 `[CardEffect]` + 反射自动注册效果定义；将伤害、治疗、消灭、强化、回手、抽牌、费用、召唤、复活、沉默等效果收敛到统一 schema，提升扩展和维护效率。
- **同步运行时与模拟语义**：每个效果同时实现真实对战执行与 `BattleStateSnapshot` 模拟逻辑，保证 AI 搜索、目标评分和实际结算使用同一套规则，降低“AI 认为可行但运行时不一致”的问题。
- **实现条件分支和目标规则**：支持触发条件、then/else 分支、指定/随机/全体/自身目标模式，以及潜行、魔免、守卫、墓地复活等特殊规则，覆盖复杂卡牌效果组合。
- **开发卡牌数据库编辑器**：基于 EditorWindow + UI Toolkit 实现卡牌编辑工具，支持卡牌搜索、筛选、排序、新建、复制、删除、效果配置、被动配置、AI 参数配置、校验提示、卡面预览、Undo 和保存，提升配置效率。
- **实现卡牌数据迁移与校验**：通过 `CardEffectMigrationService` 对旧效果数据递归迁移到新 schema，并配套 `CardValidationService` 检查缺失参数、异常配置和兼容问题，避免旧资源拖累后续扩展。
- **接入 MCTS 对局决策**：基于快照模拟构建 AI 行动搜索，处理合法动作、目标评分、斩杀选择、守卫规则、隐藏信息抽牌和短路搜索等情况，使 AI 能完成整局自动对战。
- **完善测试与调试闭环**：使用 Unity Test Framework 建立 EditMode 41 个用例，覆盖效果数值、被动组合、AI 规划和数据校验；PlayMode 冒烟测试可加载 BattleScene 并由双方 AI 托管跑完整局至胜负判定。
- **提升验证效率**：实现运行时 GM 调试面板，支持发指定卡牌、填场/清场、设置生命/费用、结束回合、时间倍率、跳过动画和 AI 托管，便于快速复现场景和验证问题。

AI 训练相关：预留并接入了模型配置、数据集与模型晋升链路，用于后续策略模型迭代。

### 面试讲解角度

- **设计思路**：把“卡牌效果”从散落的分支逻辑中抽出来，统一为效果定义、目标规则、参数 schema、运行时执行、模拟执行和编辑器元数据，新增效果时只需要补充一个定义类和测试。
- **复杂度处理**：将对局状态抽象为 `BattleStateSnapshot`，AI 在快照上模拟，不直接修改真实场景对象；真实结算则通过 `EffectManager` 排队处理，避免触发链、动画回调和目标选择互相打断。
- **工具化思路**：把高频、易错、重复的卡牌配置工作做成编辑器工具，并加入校验和预览，让问题尽量在配置阶段暴露，而不是进入运行时后再排查。
- **质量保障**：对容易回归的规则写成 EditMode 精确断言，对完整流程写 PlayMode 冒烟测试；新增效果时同时补充运行时语义、模拟语义和测试，避免只改表现不改 AI 或只改 AI 不改实战。

## 三、次项目：生存射击

**生存射击 | U3D 俯视角生存射击游戏 | 独立开发 | 2026/6 - 2026/7**

**技术栈**：Unity 2022 LTS / C# / UGUI / Animator / NavMesh / 对象池 / XML / ScriptableObject

**项目概述**：独立完成俯视角生存射击玩法，包含武器成长、怪物波次、商店养成、局内外升级、战斗反馈和场景切换等核心模块。

### 精简后的项目要点

- **优化高频对象创建**：设计 `PoolMgr + ObjectPool` 统一管理子弹、伤害数字等高频对象，支持预热、容量限制、生命周期回调和延迟回收，降低运行时分配压力并提升战斗帧率稳定性。
- **改进战斗反馈表现**：实现伤害数字聚合显示，在短时间内复用同一显示对象并累计伤害，同时接入对象池回收，减少重复飘字对象带来的性能开销。
- **降低系统耦合**：抽象武器基类和升级接口，使用事件中心解耦模块交互，并用 XML / ScriptableObject 管理武器属性、怪物波次和商店配置，使新增武器和功能主要通过派生逻辑与配置完成。
- **优化场景切换体验**：使用 `LoadSceneAsync` 实现异步场景加载，控制场景激活时机并同步更新进度条、百分比和 loading 动画，减少主菜单进入战斗时的卡顿感。

## 四、解决问题的思路

### 1. 先定位问题类型

遇到问题时先区分是性能瓶颈、规则复杂度、配置错误、状态时序问题，还是验证效率问题。例如 ArkCard 中卡牌效果持续增加后，真正的问题不是某个效果难写，而是运行时、AI 模拟和编辑器配置缺少统一边界。

### 2. 抽象稳定边界

对变化频繁的内容做配置化，对规则稳定的内容做接口化。ArkCard 中将效果拆成 `ICardEffectDefinition`、`CardEffectData`、目标规则、运行时动作和模拟动作，使卡牌扩展不需要频繁修改核心流程。

### 3. 优先让问题可复现

对运行时问题，通过 GM 面板快速搭建指定血量、费用、手牌、场地和回合状态；对规则问题，通过快照和 EditMode 测试构造最小场景，先确认问题能稳定复现，再修改实现。

### 4. 用自动化锁住规则

对容易被新卡牌、新效果影响的能力写回归测试。ArkCard 将效果数值、被动组合、AI 规划和完整对局分别放进 EditMode / PlayMode 测试，确保后续扩展时能及时发现行为变化。

### 5. 保持运行时和工具链一致

编辑器工具不只是录入数据，还要做校验、迁移、预览和 Undo 支持；AI 模拟不只是单独的一套逻辑，而要与真实效果结算保持一致。这样可以减少“配置能保存但运行时报错”“AI 测试通过但实战异常”这类问题。

## 五、后续找工作的建议和方向

### 求职方向

- **优先方向**：Unity 游戏客户端实习，重点投玩法系统、战斗系统、卡牌/回合制、独立游戏和中小型项目组。
- **次优方向**：Unity Gameplay 开发、Unity 工具链开发、客户端内容工具开发。
- **暂不主推方向**：纯图形渲染、热更新框架、底层引擎、强商业化 SDK 接入岗位，除非后续补充更强项目证据。

### 简历调整建议

- 把 ArkCard 放在项目经历第一位，作为主项目讲深；生存射击作为第二项目压缩展示，证明有不同玩法品类和性能优化经验。
- 项目 bullet 尽量采用“做了什么 + 解决什么问题 + 结果是什么”的结构，减少长段问题描述。
- 技术栈只写能在项目中讲清楚的内容，不建议堆叠 NGUI、热更新、图形学等缺少当前项目支撑的关键词。
- 准备 2-3 个能讲深的案例：统一效果系统重构、卡牌编辑器工具、MCTS 与快照模拟、对象池性能优化。

### 面试准备重点

- **C# 基础**：集合、泛型、委托/事件、协程、Task、反射、值类型/引用类型、GC 与装箱。
- **Unity 基础**：生命周期、UGUI、Prefab、ScriptableObject、资源加载、动画状态机、协程时序、对象池、场景加载。
- **玩法系统**：回合流程、状态机、技能/效果系统、目标选择、Buff/被动、数值结算、事件驱动设计。
- **工程化**：asmdef 拆分、EditorWindow 工具、Undo/SerializedObject、自动化测试、调试面板、日志定位。
- **算法与数据结构**：数组、链表、栈队列、字典、排序、搜索、树、简单图搜索；能结合 MCTS 项目经历解释搜索和评估思路。

### 作品展示建议

- 给 ArkCard 补充一个清晰的 GitHub README：项目简介、核心系统、编辑器截图、测试覆盖、运行方式和已知限制。
- 录制 1-2 分钟 Demo 视频：展示卡牌编辑器配置、运行时对战、GM 面板快速复现、AI 托管完整回合。
- 在简历项目链接旁标注“含编辑器工具、自动化测试、AI 托管对局”，让面试官第一眼看到区别于普通课程项目的部分。
- 面试讲项目时先讲架构，再讲一个具体问题的定位和改造过程，最后讲测试如何保证后续扩展不回归。
