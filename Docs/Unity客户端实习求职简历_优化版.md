## 项目经历

### 卡牌游戏 | U3D 策略卡牌对战 | 独立开发 | 2026/7-2026/8

**项目地址：** [ALVIN23333/ArkCard: 类炉石传说卡牌](https://github.com/ALVIN23333/ArkCard/tree/main)
**技术栈：** Unity 2022 LTS / C# / UGUI / ScriptableObject / EditorWindow + UI Toolkit / Unity Test Framework / MCTS / PrimeTween

**项目概述：** 独立开发 2D 策略卡牌对战项目，完成卡牌数据配置、手牌与场地管理、回合流程、卡牌效果结算、目标选择、AI 托管、编辑器工具、自动化测试和调试面板等客户端核心链路。

- 随着卡牌数量和效果类型增加，原本分散的效果逻辑会让新增卡牌同时牵动运行时、AI 和编辑器。为此设计 `EffectRegistry` 作为统一效果入口，通过 `[CardEffect]` + 反射自动注册效果定义，并用 `CardEffectData` 统一描述效果类型、目标方式、阵营范围和数值参数，将伤害、治疗、消灭、强化、回手、抽牌、费用、召唤、复活、沉默等效果收敛到统一 schema，新增效果时只需补充定义类、编辑器入口和测试，核心流程无需大改。
- AI 需要在不影响真实场景对象的情况下预估行动收益，因此为每个效果同步实现真实对战执行与 `BattleStateSnapshot` 模拟语义，让 AI 在快照上完成合法动作搜索、目标评分、斩杀判断、守卫规则和隐藏信息处理。这样 AI 决策与实战结算可以共用同一套规则边界，减少“AI 认为可行但运行时异常”的情况，并支持完整对局自动托管。
- 卡牌属性、被动、效果和 AI 参数较多，直接维护 ScriptableObject 容易出现参数缺失、旧数据兼容和录入效率低的问题。基于 EditorWindow + UI Toolkit 开发卡牌数据库编辑器，支持搜索、筛选、排序、新建、复制、删除、效果配置、被动配置、AI 参数配置、校验提示、卡面预览、Undo 和保存，把卡牌制作流程工具化，让配置错误尽量在编辑阶段暴露。
- 旧效果数据迁移到新 schema 时，需要兼顾嵌套分支和历史卡牌兼容性。通过 `CardEffectMigrationService` 使用 SerializedObject 递归迁移顶层效果、then/else 分支和旧枚举参数，并配套 `CardValidationService` 检查缺失参数、异常配置和兼容问题，使旧卡牌数据可以平滑升级到统一效果结构，后续扩展不需要保留大量临时兼容逻辑。
- 卡牌效果和被动组合复杂，手动测试很难覆盖伤害、治疗、复活、沉默、潜行、守卫、斩杀等边界情况。使用 Unity Test Framework 建立 EditMode 规则测试和 PlayMode 冒烟测试，EditMode 覆盖效果数值、被动组合、AI 规划和数据校验，PlayMode 加载 BattleScene 并由双方 AI 托管跑完整局，形成可回归的质量保障链路。
- 调试复杂局面时，反复手动搭建卡牌、血量、费用和场地状态比较耗时。实现运行时 GM 调试面板，支持发指定卡牌、填场/清场、设置生命/费用、结束回合、时间倍率、跳过动画和 AI 托管，可以快速复现场景并验证战斗规则、动画流程和 AI 行为。
- **AI 训练相关：** 预留并接入了模型配置、数据集与模型晋升链路，用于后续策略模型迭代。

### 生存射击 | U3D 俯视角生存射击游戏 | 独立开发 | 2026/6 - 2026/7

**项目地址：** [ALVIN23333/unity2: rougelike俯视角射击](https://github.com/ALVIN23333/unity2)  
**技术栈：** Unity 2022 LTS / C# / UGUI / Animator / NavMesh / 对象池 / XML / ScriptableObject

**项目概述：** 独立完成俯视角生存射击玩法，包含武器成长、怪物波次、商店养成、局内外升级、战斗反馈和场景切换等核心模块。

- 战斗中子弹、伤害数字等高频对象会反复创建和销毁，容易造成内存抖动和帧率不稳定。为此设计 `PoolMgr + ObjectPool` 统一对象池，支持预热、容量限制、生命周期回调和延迟回收，并将高频对象接入复用流程，降低运行时分配压力，提升战斗场景帧率稳定性。
- 怪物连续受击时会生成大量伤害数字，既分散画面信息，也增加对象创建压力。设计伤害数字聚合显示逻辑，按怪物实例追踪当前伤害数字，在短时间内复用同一显示对象并累计伤害，同时接入对象池回收，提升连击反馈清晰度并减少重复飘字对象带来的性能开销。
- 武器、升级、商店和怪物波次不断扩展后，模块之间的耦合会逐渐上升。通过抽象武器基类与升级接口、使用事件中心解耦模块交互，并用 XML / ScriptableObject 管理武器属性、怪物波次和商店配置，使新增武器和功能时主要补充派生逻辑与配置，核心框架无需大规模改动。
- 主菜单进入战斗场景时如果直接切换，缺少过渡反馈且容易产生卡顿感。使用 `LoadSceneAsync` 实现异步场景加载，控制场景激活时机，并同步更新进度条、百分比和 loading 动画，优化场景切换过程中的用户反馈和过渡体验。
